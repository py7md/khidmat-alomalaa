# الأمان والتشغيل الإنتاجي

- لا تضع `.env` أو `WHATSAPP_ACCESS_TOKEN` أو `META_APP_SECRET` أو `ADMIN_TOKEN` في GitHub. تحفظ هذه القيم في Vercel كـ Secret.
- في وضع `WHATSAPP_PROVIDER=meta` يجب أن يحتوي Webhook على ترويسة `x-hub-signature-256` صحيحة؛ الطلبات غير الموقعة تُرفض بـ 401.
- يرفض Webhook JSON غير الصالح والحمولات الأكبر من 256KB والرسائل النصية الأكبر من 4096 حرفًا.
- تمنع المحاكاة أكثر من 30 طلبًا لكل عنوان مصدر خلال الدقيقة. هذا حد محلي لكل Function instance، وللإنتاج عالي الحجم استخدم Redis أو Vercel Firewall.
- `/api/handoffs` يتطلب `Authorization: Bearer ADMIN_TOKEN` ولا يعمل إذا بقيت قيمة `local-admin` الافتراضية.
- منع التكرار في الذاكرة يحوي مدة صلاحية وحدًا أقصى، لكنه ليس بديلًا عن Redis المشترك بين نسخ Vercel.
- يجب استخدام PostgreSQL وRedis خارجيين عند تشغيل أكثر من نسخة أو الحاجة إلى حفظ دائم للمحادثات والحجوزات.
- إذا فشل إرسال Meta، تُحرر الرسالة من حالة `processing` حتى تسمح إعادة Webhook بالمحاولة مرة أخرى؛ لا تُسجّل كمرسلة قبل نجاح المزود.
- أحداث Meta التي لا تحتوي رسالة نصية، مثل تحديثات الحالة أو الصور غير المدعومة، تُؤكّد بـ 200 مع `ignored` بدل إعادة المحاولة بلا فائدة.
